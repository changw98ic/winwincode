Context & Memory Runtime · Architecture Spec

长程 Agent 只关注现在重要的信息，但不真正遗忘已验证的事实

Jev 不是「又一个 compaction 插件」。它是 WinWinCode 独立的 Context & Memory Runtime：Deterministic GC + Jev 决策模型 + Working/Long-term Memory + Context Materializer + Provider Policy + Thread Rotation。Compact 只回答「窗口快满了怎么办」。

JEV DECISIONS

Jev 模型做什么、不做什么

Jev 是专门做决策的模型（如 OpenJev NLI：premise + hypothesis → entailment / contradiction / neutral）。业务层不得绑死某一家 Provider。Jev 不改验证结论、不绕过 Controller、不杀 Worker。

PIN 钉住不可回收 KEEP 完整保留 TRUNCATE compact 主路径 DROP 丢弃 ARCHIVE 归档
模式 行为
token compact 默认 默认开启——常规路径上的压缩
Jev GC 启动（50–60%） 关闭默认 compact，改由 Jev 模型决策回收
压力回落后 恢复默认 compact（实现时写清恢复条件）
低置信度 默认 KEEP，绝不默认 DROP

EPIC MAP · JEV-01 … JEV-18

规格全景（可筛选）

JEV-01

Jev Runtime 抽象层

统一 JevProvider：evaluate / batch / health / capabilities。Local OpenJev、Remote API、Mock、未来模型可替换。

  • JEV-001 Interface
  • JEV-002 OpenJev Adapter（hypothesis scoring）
  • JEV-003 Remote + fallback / skip
JEV-02

Jev Decision Engine

NLI 概率 + 系统 policy → 决策。不让模型吐分类字符串。

  • Context Retention PIN/KEEP/TRUNCATE/DROP/ARCHIVE
  • Memory Write / Importance / Supersede / Rerank
JEV-03

Deterministic Context GC

确定能删的不浪费 Jev：tool result 分类生命周期、文件去重、shell/test/grep 规则。

JEV-04 / 05

Working & Long-term Memory

独立于 Conversation 的 Working Memory schema；provenance、confidence、pinning；episodic/semantic、versioning、memory GC。

JEV-06

Context Materializer

Jev 只判断，模型最终看到什么由 Materializer 决定：budget、P0–P4 优先级、关键字段 verbatim 保留。

JEV-07

Provider-aware Policy

不同模型不共用同一阈值：capability profile、动态 GC、cache-aware（分类可频繁、mutation 必须低频）。

JEV-08

Thread Rotation

Task lifetime ≠ Conversation lifetime。Generation 模型、事务性切换、bootstrap 10K–30K、失败保留旧 thread。

JEV-09

Auto Compact 协同

不删除原生 compact。模式 native / jev / hybrid / disabled；Jev-first：先 GC，回到安全区则 skip native compact。

JEV-10

Benchmark 系统

Session Replay + 指标 + 成本模型 + 24h soak。拒绝「感觉 token 好像少了」。

JEV-11 / 12

Observability / UI

Jev Trace、Context/Memory Timeline、Token Saving Dashboard；Session 页 Context 占用与 Inspector。

JEV-13

Safety & Failure Recovery

Fail-open、低置信 KEEP、Critical 永不删、GC/Rotation 前 snapshot、rollback 旧 Generation。

JEV-14 / 15

本地推理与数据集

CUDA/MPS/CPU、量化决策精度、Warm Pool 禁止每次 load 4B；真实 session 标注后再考虑 WinWinCode-Jev 微调。

JEV-16 / 17

配置与 Feature Flags

contextRuntime yaml；独立开关 jev.contextGc / memoryWrite / rotation / nativeCompactInterception 便于 A/B。

JEV-18

测试矩阵

Unit / Integration / Failure（timeout、crash、OOM、rotation 失败）/ Regression：被 DROP 内容不得导致任务失败。

当前筛选下没有 EPIC。

JEV-03 · DETERMINISTIC

确定性 Tool Context GC

类型 确定性规则
file_read v1 在 v2 之后默认失效；保留 latest snapshot + 必要 diff
shell 删除重复 pwd / ls / git status / package listing
test 保留最新失败、最新成功、关键 regression；旧失败 → archive
search / grep 被新结果覆盖 → archive/drop；保留后续决策引用的 evidence
其余 tool 类型 shell / write / build / lint / git / browser / mcp / agent 各自策略

JEV-04 / 05 · MEMORY

Working Memory 与长期记忆

Schema

Working Memory 字段

task goal acceptanceCriteria constraints decisions currentPlan currentState modifiedFiles activeErrors verifiedFacts failedAttempts pendingWork openQuestions activeRisks

Provenance

可追溯

来源：conversation / tool / file / test / verifier / user / system / agent； 记录 event id、thread id、workrun id、timestamp。禁止无来源「AI 记忆」。

Confidence

置信分级

USER_ASSERTED · SYSTEM_VERIFIED · TOOL_OBSERVED · AGENT_INFERRED · UNKNOWN。 系统验证优先于模型推测。

Supersede

不物理删除

B supersedes A 时写 { status: "superseded", supersededBy: "memory-b" }， 保留决策演化。

JEV-06 · MATERIALIZE

Context Budget 与优先级

contextBudget:
  system: 5%
  task: 10%
  pinnedMemory: 10%
  workingMemory: 15%
  recentHistory: 30%
  retrievedEvidence: 20%
  buffer: 10%
优先级 内容
P0 System · User Constraint · Acceptance Criteria
P1 Current Goal / Plan / Failure · Latest Verification
P2 Relevant Memory · Recent Tool Result
P3 Historical Evidence
P4 Old Logs（超限先删）
Verbatim 禁止 summary： exact error、文件路径、行号、测试名、CLI 命令、API response、关键用户原话、验收标准。

JEV-08 · ROTATION

Thread Rotation（80–85%）

Task 拥有多个 Thread Generation。触发：context 阈值、阶段边界、质量下降、 provider 限额、手动。新 Thread bootstrap 目标 10K–30K，而不是把 Jev KEEP 的几十万 token 全塞回去。 

FREEZE → Snapshot → Build Bootstrap → Validate
→ Create New Thread → Inject → Verify State
→ Switch Active Thread → UNFREEZE
# 任一步失败：old thread remains active
Worker 独立性： Rotation 不得杀死 Worker / Sub-Agent，不得丢掉 Tool Job、Approval、WorkRun，不得改 Git Worktree 或 Task 状态。

JEV-09 · COMPACT

与原生 Auto Compact 协同

模式 含义
native 仅原生 compact
jev Jev 接管（GC 启动时关默认 compact）
hybrid Jev-first：Deterministic → Jev → 重算；安全区内 skip native
disabled 关闭（仅测试/对照）

JEV-13 · SAFETY

Fail-open 与保护项

Fail-open

Jev 不可用 → Coding Agent 继续运行；禁止 Worker failed。

Low confidence

confidence < threshold → 默认 KEEP。

永不自动删除

user constraint、acceptance criteria、system instruction、active blocker、 latest verification、pending approval。

Snapshot / Rollback

GC/Rotation 前 snapshot；bootstrap 失败立即切回旧 Generation。

JEV-10 · GATE

Benchmark 与 Phase 1 门槛

对比：baseline vs jev vs jev+memory vs jev+memory+rotation。24h 级 soak 才算长程验证。

指标 Phase 1 目标
主模型 billed input ↓ ≥ 15%
重复 Tool Calls ↓ ≥ 15%
Jev 额外成本 ≤ 主模型节省的 10%
Task Success / Verification 不得低于 baseline
Critical Context Recall ≥ 99%（应 KEEP 被 DROP ≤ 1%）
Memory-related Regression < 2%
第一批必须先回答：OpenJev 对真实 Coding Agent Context 的 KEEP/DROP 准确率够不够。 垃圾误 KEEP 可接受；应保留却被 DROP 危险。系统天然宁愿多留，不要错删。

JEV-16 · CONFIG

配置示意

contextRuntime:
  enabled: true
  jev:
    provider: openjev
    model:
      id: AlexWortega/openjev
      device: auto
    batchSize: 16
  gc:
    enabled: true
    observeEveryTokens: 24000
    lowConfidenceAction: keep
  memory:
    enabled: true
    workingMemory: true
    episodicMemory: true
    semanticMemory: true
  rotation:
    enabled: true
    bootstrapMaxTokens: 24000
  compact:
    mode: hybrid   # 默认 token compact 开启；Jev GC 时关闭默认 compact

Feature flags（独立开关便于 A/B）： jev.contextGc · jev.memoryWrite · jev.memoryRerank · jev.memoryGc · jev.rotation · jev.nativeCompactInterception

DEFINITION OF DONE

不能以「已经接入 Jev」收工

  • OpenJev 本地运行
  • Remote Jev fallback
  • Context GC 工作
  • Memory 分类 / 生命周期工作
  • Memory Retrieval 工作
  • Thread Rotation 不丢 Task State
  • Provider-aware policy 工作
  • Jev 故障不影响 Worker
  • 所有 Decision 可审计
  • 24h Coding Session 成功完成
  • Critical Context Recall ≥ 99%
  • Task Success 不低于 baseline
  • billed prompt token 至少下降 15%
  • 重复 Tool Operation 至少下降 15%
  • 无新增不可恢复状态错误
