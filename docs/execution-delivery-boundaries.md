# Worker 消费与交付边界

## 接收、交接和派发的统一阶段

`accept_control` 的成功只表示本条消息已经可靠消费，包含必要的后续意图交接。它不调用端口或 Provider。业务处理器使用 `enqueue_effect` / `enqueue_retained_effect`，Core 批次通过 `enqueue_codex_effects` 进入已有 outbox；`execution_effects.rs` 的驱动器单独调用 `dispatch_execution_effect` / `dispatch_retained_effect`。没有按控制消费上下文切换行为的发送开关。

| 阶段 | 成功表示什么 | 谁推进 |
| --- | --- | --- |
| 控制消费 | 校验及当前操作可靠完成，后续工作已交接 | Worker 与生产 Adapter 的对应持久化入口 |
| 效果入队 | 原消息身份、内容及重放意图已保存 | 原业务生产者 |
| 效果派发 | 远程帧被接受，或设备模型通道已处理交接 | 有界 outbox 驱动器；两种结果有独立类型 |
| 执行完成 | 原尝试产生确定的完成、失败或取消事实 | Kernel / Worker |
| 候选交付 | 候选摘要与全部内容获得合法确认 | Artifact 协议 |
| 业务验收 | 必要 Evidence 与当前 Candidate 支持 Verdict | Control Plane |

模型结束、候选交付和业务验收可以处于不同阶段。用量未知、普通日志缺失不修改执行事实；必要产物或证据未完成也不能被辅助流程改写成验收通过。

Core 的状态与必要 outbox 批次在相应 SQLite 事务中交接。Observer 的 ChangeBatch journal 与 Codex outbox 是两个现有存储：先保存原请求，再幂等采用完全相同的请求到公共 outbox；中断后由 journal 恢复交接。这里不声称跨数据库事务原子性。两端交接尚未完成时不确认当前控制，重试依赖精确身份的幂等操作。

## 唯一的重试责任

| 工作 | 重试责任与唤醒 | 取消、拒绝或超时出口 |
| --- | --- | --- |
| 控制消息 | Server 的原消息重放；Worker 完成可靠消费后确认 | 校验或持久化失败保持未确认；后续网络失败不撤销消费 |
| 运行帧、交互请求、产物、终态 | Worker 的有界 outbox 驱动，控制确认或下一 drive tick 唤醒 | 永久拒绝归档；临时断连保留；背压立即让出当前批次 |
| 确定未启动的 Device 调用 | 同一 outbox 原请求，槽位释放或下一 drive tick 重试 | 首次调用前复核当前授权与期限；取消禁止首次启动 |
| 已启动的模型调用 | Provider 存储按原 exchange 恢复响应或中断事实 | 不新建调用身份、不再次收费 |
| 远程模型调用 | Core / Observer 的持久化生产者明确交接原请求，Gateway 按原身份去重恢复 | 通用队列扫描不擅自重发无人交接的付费请求 |
| 新的业务尝试 | 任务层明确创建新的 attempt / fencing | 旧尝试的结果保持不变 |

Observer journal 保留业务观察状态；模型原始请求的授权证明统一来自公共 outbox，派发器不读取角色专属证明。首次合法响应或取消回执会结束原 `ModelOpen` 的 pending 生命周期，但保留原始请求供续租及迟到结果校验。有效期延长不修改原帧、exchange 或调用 ID。

Worker 的 `DriverClock` 成对保留墙钟和单调锚点。新采样落后于单调估计时保留原锚点；首次调用同时用“锚点 + elapsed”校验租约签发下界与到期上界，单调 deadline 仍从原采样对计算。拒绝任务的时间戳也使用当前估计时间。保留旧锚点不拒绝后来签发的合法新任务，时钟回拨不延长授权。

每次 Codex poll 至多在结果消费前后各派发一个有界批次。首批失败后仍可消费结果并保存后续工作，但本轮不再次派发；下一轮控制消费、心跳及驱动提供唤醒。注册和显式心跳是独立驱动入口，不在控制处理器中执行。端口超时约束单次交换；租约过期、取消、永久拒绝与任务终态提供明确出口。

心跳的可重试 `SequenceGap` 只在原 worker、instance 和序号的持久化请求或已应用正向证明存在时消费。它不删除请求、不表示心跳已接受；Worker 将截至该序号的原心跳重新入队并清除发送缓存，由驱动顺序重放。Server 分别派生 Gap 与正向 ACK 的稳定传输身份，Accepted 与 Duplicate 共用正向身份，迟到的 Gap 确认不能删除正向 ACK。消息结构保持 v1；恢复这条链路需要部署修复后的 Worker 与 Server，旧 Worker 仍会拒绝 Gap，旧 Server 仍可能将正负 ACK 合并。

远程交互的传输确认先保存精确消息、路由、授权和内容摘要的独立证明，再尝试原帧删除及安全 WAL checkpoint。删除或 checkpoint 暂时失败时，证明保留；下一次认证交换（即使没有重复 ACK 或上行被背压）及驱动 tick 独立重试。重启后的 claim 跳过已证明消费的原帧。只有清理完成才删除证明和内存待确认项，未经确认的消息仍保留重放。合法续租沿原授权历史清理，已终结 slot 使用原终态清理，不启动执行、不产生验收成功。该表是兼容的元数据迁移；回退版本不驱动这些证明，需要恢复当前版本才能继续独立清理。

## 辅助失败和必要失败的范围

`WorkerMain::accept_control` 负责校验、应用并持久化当前控制消息。审批、人工输入、动作许可、模型响应、产物 ACK 和任务派发都在这个入口可靠交接后续待发意图，再允许传输确认。网络发送由驱动循环完成；后续发送失败不会撤销已经完成的控制消费。身份、摘要、顺序或持久化失败仍返回错误。Core 与动作许可的消息批次在一个 SQLite 事务中进入 outbox，事务失败时恢复内存队列。

背压和暂时断连结束当前发送批次，保留未接受的上行帧。每批沿用 64 条、512 KiB、250 毫秒的调度预算；首帧独立处理，单次交换由端口超时约束。Server 在背压时仍接收传输确认并返回控制消息，Worker 随后消费、确认并继续拉取。

交互回执按精确请求关联键及已应用结果摘要幂等。新增 `execution_response_receipt` 表与请求确认在同一事务提交；同类其他请求不参与旧回执合法性判断。注册、心跳重放只归一化传输时间和 accepted/duplicate；模型首个响应与后续取消分别保留证明。旧版本已清理的回执需要现有审批、输入或动作许可持久化事实才能补存证明；没有证明的陌生回执仍被拒绝。

模型开始／完成、取消及已完成 turn 恢复中的普通统计写入，以及启动时的性能补写，都按尽力记录处理。业务帧持久化、ProviderFinal、Core 提交及必要产物仍是可靠完成的前提。性能行缺失时，预算聚合从模型调用账本保留精确调用数和完成事实，并把未观测用量／费用标为 unknown；显式用量或费用预算继续要求完整账务，不能把丢失统计当成零。

JEV 回执读取或部分导入失败时，模型业务结果仍可交付，但 `model_call_ledger.jev_accounting_complete` 与 ProviderFinal 一起可靠保存未完成的账务证明。总量必须保持 unknown，不能把缺少回执行解释为没有发生调用。旧库升级时该标记默认为未完成；只有精确回执重新核对成功才能提升完整性。JEV 父操作的生命周期由对应模型调用账本的 ProviderFinal 关闭，不依赖可选 Primary 性能行；中断的 JEV 用量继续未知。

Observer 的首次结算在当前 batch 校验之后保存独立的 `observer_settlement` 回执，再尽力更新性能投影。精确重放先匹配该回执，因此 batch 转换或终态不会使已经接受的结算变为冲突；变更用量、跨运行身份和未经认可的首次结算仍被拒绝。Observer 用量聚合读取该回执，性能投影失败不阻止业务收尾，也不重复统计。旧版已经结算的 Observer 可用其当时必需的已完成性能记录恢复回执：只认可同一 run/batch 及匹配的用量/费用，缺少或变更证明继续拒绝。新表和列为增量升级；旧版程序会忽略这些证明，运行中的任务应保留当前版本处理，不能依赖回退后的旧预算语义。

历史 Observer 终帧按原请求、完整授权与已保留帧摘要重放，不受随后 batch 的 Applying、ValidationPending 或 ObservationPending 阶段影响；不得推进新 batch 的状态、改动工作区或重复结算。首次 Observer 结果仍要求当前观察意图匹配。

Control Plane 的最终模型确认保留原传输摘要及结算回执，另用独立的 `internal_provider_exchange_final_ack_semantics` 表保存经过权威核对的确认事实。仅归一化传输 message ID、时间及 Accepted／Duplicate 状态；租约、session、exchange、最终序号、错误与重放请求仍校验。旧库首次重放从原请求与完整终态回执重建该证明，原摘要保持不变；重启不重复调用 Provider 或释放流。旧版本会忽略新证明，不能依赖回退后的 Duplicate 兼容性。

验证命令的输出读取和进程退出共用一个绝对截止时间。提前关闭 stdout/stderr 不能取消退出期限；超时仍终止并回收原进程组及其后代。

普通性能报表读取、聚合或保留失败不会改变业务终态，也不会阻止结果返回。终态用量读取失败保留已存用量，或明确给出 unknown；新增付费调用仍使用原有权威账本和硬预算检查。产物、必要验证证据及业务判定继续校验，缺失证据不能变成通过。

已登记的 Core 模型调用可以在过期后消费精确的 `LeaseExpired` 失败终帧。入口要求无成功正文、不可重试、完整原请求证明、未取消且当前身份仍一致；续租不得改变 attempt、fencing、Worker 或 session。该分支只关闭原调用和确认回执，不能启动工作或接受过期成功。重复终帧匹配持久化游标与帧摘要，重启不重新交付、不重新收费；外来或替换身份仍拒绝。

Device 将同一实时授权检查传给 JEV/Judge 准备过程：每个新评分操作在可靠占用身份前检查，每次 Provider 重试及备用路由调用在实际调用前再次检查。过期时不发起下一次调用，身份占用前被拒绝的操作不建立未知账单；已开始调用的结果照常保存。精确的已完成或未知结果可以在授权到期后读取，重放不重新收费，改动原请求仍拒绝。主模型启动继续独立检查授权。

Device 本地容量不足或线程创建失败表示请求确定尚未启动，返回独立的 `ModelStartDeferred`，所有角色的原 `ModelOpen` 身份保留在同一 outbox，容量恢复后正常驱动重试。本轮结束发送批次后仍消费本地响应，完成的调用可以释放槽位。Device 持久化存储对已经启动或完成的相同调用去重，恢复已有结果或中断事实；不创建新的收费调用身份。远程付费调用继续由 Core 恢复路径管理。

本地/上行尺寸超限属于单条消息拒绝，不设置连接级终止错误。已明确拒绝的 Usage 统计帧可以保存一个小的传输投影，保留原 message ID、event ID、序号和租约，移除报表正文并给出不可用摘要，避免运行时序列缺口。原始内容保留在独立 `execution_delivery_disposition` 表，重启、Core 重放和 Gap 重放复用同一投影。必要证据不使用该降级。

必要消息永久拒绝时，保存拒绝事实、停止对应任务并保留明确的基础设施失败出口；无关任务可继续驱动。拒绝后中断的任务在下一轮根据持久化拒绝事实收尾。失败帧退出 pending，重放不能复活。原始业务终态或已冻结候选不被改写；终态本身无法交付时，Worker 给出明确的交付错误；重启恢复按原 Worker 实例隔离，新实例不继承旧实例的终态拒绝标记。连合法的小投影也无法交付、认证失效或协议不可解释时，连接按明确错误退出。

同一租约续期保留原候选上传身份，只在所有其他权威字段完全一致时接受原上传或当前续期租约的 ACK；当前 ACK 转回原上传权威进入持久化账本。跨 attempt 替换仍要求原有替换证明。

Control Plane 对待发产物和运行事件使用同一租约窗口证明：窗口变更只能来自 Registry 已接受的 claim／renewal 回执，完整 Job、payload、attempt、lease、fencing 和 Worker 身份必须与当前租约一致。任意较早到期时间都不是历史授权。原帧不改写；运行事件首次接收仍检查当前 Server 时间，已接收回执的精确重放按原事实确认。

候选取消意图禁止继续发送；完成清理时新增 `candidate_artifact_cancelled` 元数据证明。精确、合法的迟到 ACK 可以消费，但不推进候选、不重放内容、不生成成功结果。外来身份和越界序号仍拒绝。已接受候选不可取消；取消后的同一权威不可重新 retain，新 fencing attempt 可建立新上传。旧版本已删除且未留证明的取消记录无法事后重建。

委托 `submit_change_batch` 通过 custom tool 交接提案时，Core 在结束该 turn 前保存匹配原 call ID 的 `CustomToolCallOutput`，内容仅说明交给 Host 做应用和验证。下一 Composer 请求保留原 call 与唯一交接回执；该回执不替代 workspace 验证、Observer 决策或业务 Verdict。

新增表采用兼容的独立元数据，不修改已有 outbox 的状态约束；原始帧和拒绝证明继续用于审计。回退版本可能忽略这些新证明，涉及未结束任务时应恢复当前版本后继续处理。

回归使用 Rust 原生 Worker 生命周期、生产 Adapter/Kernel 与本地脚本化 Control Plane/Provider，以及真实 SQLite 故障注入。容量和线程启动拒绝使用 Device 本地通道定向测试；这些结果不代表真实 Device 或付费模型验收。

## 共用生命周期回归

生产 Worker、Adapter、Kernel helper 与 SQLite 的脚本化 Control Plane / Provider 回归对模型响应、Artifact ACK、运行确认、审批、动作许可和人工输入复用同一断言：消费期间端口调用次数不增加，只有显式驱动允许派发。派发断连后检查原 pending 内容保留，恢复完成和重放不增加原调用次数；工具统计写入故障与缺失用量共同注入，业务成功和候选保持。

首次启动授权回归从公共 outbox 读取完整原请求，检查合法续租、当前过期、取消、子角色身份与同 exchange 内容变更。Observer 的实际工作区/journal 回归检查采用原请求、未启动重试、续租后的原响应、一次决策及重复回执。仅外部模型使用本地可控替身；真实 Device 和付费验收另行运行。

## 验收 Runtime 的恢复边界

同目录恢复使用原证书、端点、Device 连接授权和仓库绑定。受控源仓库只在首次建立时提交；恢复核对冻结输入摘要、HEAD、已提交文件及工作区清洁状态，再复用原基线。输入变更或源目录被修改时拒绝恢复，不重写原产物。设备先完成本次 instance 的 hello 确认，已有本人连接授权从公共 Client 目录核对；占用恢复完成后才继续派发。注册和 drain 使用精确 `worker.get`，不依赖历史 Worker 在分页列表中的位置。

临时 Control Plane 根的创建、续期、释放和回收共用父目录外侧的稳定锁文件。父目录必须属于当前有效 UID，且其他 UID 没有写权限；锁文件必须是当前 UID 所有的单链接普通文件，权限为 0600。父目录及锁文件的符号链接、可读的旧锁文件、硬链接和外来所有者均拒绝，保留现有内容。进程退出释放文件锁，删除某个临时根不会删除锁 inode；读取共享父目录的其他 UID 无法取得这个锁。
