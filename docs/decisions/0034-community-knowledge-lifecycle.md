# 0034：Community 知识确认、授权与删除

Community 只保存当前用户的个人知识和仓库知识。团队共享、团队 ACL 与跨用户学习不在该产品边界内。知识目录复用 `ProductStateStorage`，不再建立第二套索引数据库、摘要库或缓存。

## 生效规则

- 机器建议、用户新建和用户修改都先进入 `suggested`；只有用户显式确认后才能进入模型上下文。
- 来源版本变化后进入 `needs_reconfirmation`。过期、归档、撤销和待确认条目都不进入模型上下文。
- 仓库知识仅在调用者当前拥有该仓库权限时可读。来源另有仓库归属时，条目作用域和来源权限必须同时满足。权限过滤先于搜索匹配与计数。
- 仓库规则覆盖同名个人规则；当前用户指令和当前批准 Spec 的规则键又覆盖全部历史知识。

## 删除与恢复

删除来源时，一次目录事务清除标题、正文、规则键、作用域、来源位置和过期信息，只保留不含内容的来源墓碑。搜索只读这个当前目录，没有可回填内容的旧索引、派生摘要或缓存；同一来源标识也不能重新创建条目。

不可变的删除前备份可以按既定保留期继续保存，但不得接入在线检索。恢复备份时，恢复点之后产生的来源墓碑必须先重放，知识目录通过校验后才可开放读取；缺少这段墓碑时保持知识读取关闭。保留期结束后，由备份删除流程整代删除备份，而不是从备份内选择性改写知识。
