# ADR-0015：制品和证据使用内容寻址正文与按作业隔离的追加记录

- 状态：已接受
- 日期：2026-08-22
- 对应任务：`winwincode-9c4.6.2`
- 实现：[`packages/strongflow/src/artifact-store.ts`](../../packages/strongflow/src/artifact-store.ts)
- 测试：[`tests/strongflow-artifact-store.test.mjs`](../../tests/strongflow-artifact-store.test.mjs)

## 结论

StrongFlow 通过 `StrongFlowArtifactStore` 保存已经通过校验的正式制品、角色交接和执行证据。正文按照 SHA-256 摘要保存，元数据则按照作业写入只追加、不覆盖的连续记录。相同正文只保存一次，但这项物理去重不授予读取权限；读取、查找和分页始终从当前作业自己的记录开始。

每条元数据记录都包含：

- 正文摘要、字节数和媒体类型；
- 制品种类与制品 ID，或证据 ID、证据种类和证据可信来源；
- 角色、阶段运行、尝试和完整内核事件范围；
- 适用时的完整候选版本身份，或候选版本与差异摘要；
- 前一条记录摘要和当前记录摘要。

记录 ID 由作业 ID 和连续序号组成。制品 ID 或证据 ID 一旦发布，之后用同一 ID 提交不同正文、生产者、候选版本或时间都会失败，不会覆盖旧事实。

## 直接证据与模型观察

`publishDirectEvidence` 只生成 `trusted-direct-command` 记录，供程序直接捕获命令、测试、差异、渲染结果或日志。命令和测试证据必须带命令 ID 与退出码。

`publishModelObservation` 生成独立的 `model-observation` 记录。它必须精确引用同一作业里已经发布的正式制品，并且生产角色、尝试、内核事件范围和候选版本必须与来源制品一致。模型描述不会被包装成直接命令证据。

## 原子发布和故障处理

正文和元数据先写入随机临时文件，刷新文件内容后再通过不会覆盖已有文件的硬链接发布，并刷新所属目录。进程在发布前中断时，只会留下名称明确的待处理文件；读取器忽略待处理元数据。已经占用正式序号但内容不完整的记录会使整个作业存储进入损坏状态，不会跳过缺口继续读取。

两个进程同时发布时，只有一个进程能占用某个正式序号。另一个进程重新读取完整记录链并尝试下一个序号，因此正式记录保持从 1 开始且没有缺口。

## 读取校验和作业边界

每次读取正文都重新检查：

- 路径是普通文件；
- 文件大小等于记录值并且没有超过 64 MiB；
- 文件 SHA-256 等于内容 ID；
- 正式制品仍通过统一制品校验；
- 正文里的作业、制品身份、时间、生产者、事件范围和候选版本与记录完全相同。

元数据读取还会验证目录与清单中的作业身份、连续序号、前向摘要链和唯一身份。缺正文、正文被改、记录被改、序号缺失或跨作业记录都会明确失败。

列表每次最多返回 1000 条，并可按尝试和记录种类筛选。存储实例没有跨作业枚举或读取接口；即使两个作业复用了同一个正文文件，也只能看到各自的元数据和记录 ID。当前模块不删除已经发布的记录或正文，从而避免一个作业的保留策略误删另一个作业仍在引用的共享正文；后续清理器只能处理明确的待处理文件，或在检查所有作业引用后回收无引用正文。
