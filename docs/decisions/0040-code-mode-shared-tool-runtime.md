# ADR-0040：Code Mode 与公共工具执行

- 状态：Accepted
- 日期：2026-10-07
- 跟踪任务：`winwincode-e6ih`
- 所有权依据：[ADR-0033](0033-community-engineering-runtime.md)

## 背景

内置工具、MCP 和宿主工具需要共享授权、调用事实、结果处置、取消和恢复规则。模型需要按需发现工具，并在出现疑似循环、等待死锁或执行爆炸时取得可核对的证据。

## 决定

1. 嵌入的 Codex Core 拥有工具执行权威。模型工具面固定为 `exec` 和 `wait`。Code Mode 在内部完成按需发现、定义加载和调用编排。
2. Core 维护统一工具目录。Code Mode 读取目录的获准视图。代码对文件、进程、网络和宿主能力的访问，通过 Core 工具接口执行。
3. 所有真实工具调用进入 Core 公共执行层。公共层按实际工具身份处理授权与 hook，并将 hook 后的输入绑定到执行授权。Adapter 实现工具协议和业务语义。
4. Core 持久化逻辑请求、实际尝试、父调用、cell、等待、执行结果和交付处置。精确传输回放恢复原观测；新逻辑请求产生新观测。副作用结果未知时，依据原业务身份或下游回执核对。
5. Adapter 声明可信输入依赖、账号与会话作用域、结果有效性及恢复规则。结果复用与并发合并分别取得许可。每个逻辑等待者保留自己的结果处置和取消状态。结果读取核对当前权限。
6. 模型行为诊断默认覆盖所有任务。Core 根据调用、等待和可信进展事实生成有稳定身份与证据版本的问题。反馈随 `exec`、`wait` 或正常 yield 进入当前模型上下文，由模型选择下一步。诊断交付保留活跃 cell。
7. Worker 可靠交付 Core 事实。Control Plane、DSH 和 StrongFlow 消费统一投影，保留真实工具、父子关联、共享来源、恢复和诊断状态。
8. 任务恢复核对工具目录、策略、Kernel 接口及运行时身份。身份不匹配时返回明确恢复状态。模型上下文中的回执和诊断有固定数量与长度上限，完整事实保存在 Core 存储中。

## 验收

真实 Kernel 与产品构建的 Code Mode host 验证按需发现、授权、用户输入等待、长任务、取消、崩溃恢复、输入变化、获准复用和并发合并。诊断测试检查模型实际收到的证据与问题，以及交付后的 cell 状态。

两个 UI 使用同一份事实验证父子关系、来源和状态。上游补丁必须可重放。四个受支持发布目标分别完成安装产物运行验收。

实施工作包与逐项退出条件见[实施计划](../plans/shared-tool-runtime-plan.md)。架构流程图见[产品架构](../architecture.md)。任务验收状态保存在 Beads。
