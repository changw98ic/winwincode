## 完整响应和增量摄取

Provider 收完一次响应后，仍然统一校验结构、序列、终态和摘要。断流重试使用新的物理请求、新的 decoder 和新的物理请求计次。模型请求计次与 WorkRun 的 attempt 分别记录。失败响应的半段正文不进入下一次响应。

完整响应进入 Worker 后，每个新帧只读取需要的正文和精确游标指纹。游标头保存固定大小的进度。Adapter 对完整帧集合校验一次。重复 final 使用已保存的封条。Device 使用常驻数据库连接、数据版本和所属会话索引查询未消费后缀。

完整响应封条同时绑定原请求身份。修改源请求、正文或派生帧索引会撤销封条，或被数据库拒绝。单独重算一帧的摘要不能保留旧封条的权威。发布失败与索引写入在同一事务内回滚。

完整响应封条只由真实 Provider final 触发。本地取消只结束调用生命周期。Codex v2 完整消费者发现两者共用终态 helper 时，取消四个尚无响应的 Fusion 成员会在第一成员触发严格封条检查，阻断后续取消。原实际退出 101 的回执和精确数据库备份保留。修复将封条调用移至真实 final 入口，严格封条规则保持。原 Fusion 取消回归和两项新增实际 Rust 回归均已通过。新增夹具分别覆盖空响应、已保留前缀帧、取消完成后的数据库重新打开，以及完整 final 的封条和重复交付。数据库重新打开的观察证明源帧数量、完整游标、生命周期和封条状态保留；它不证明进程硬崩溃或源帧逐字节比较。

封条的完整帧校验、请求身份核验和发布必须处于同一个写事务。读取封条与后缀帧必须使用同一个读快照。已经开始的读取可以返回该快照内原有的完整正文；后续读取必须拒绝已撤销封条的记录。真实 SQLite 双连接回归已取得旧发布路径的两个失败，并取得同夹具的两个修复后通过。随后新增的封条 DELETE／REPLACE 守卫已包含在最终 Codex 实际回归中。已封条正文检查的固定成本不保证 SQLite 写锁取得的硬时延。

该改动针对旧实现的逐帧全历史处理。旧 2527 帧 Rust 对照处理了 3,191,601 条历史正文和 3,287,510,147 字节逻辑 JSON，正常摄取耗时 673.588 秒。这些是旧 debug 回归实测，不是正式运行逐帧计时。新版本的当前同形状 debug 摄取实测 1736.746208ms。其读取计数按帧数线性增长。这是该次实际 Rust 回归的结果；原生链结果另列。

## 原 MiMo 租约过期的因果

第三个 Provider 响应在 `2026-10-09T23:07:11.935Z` 已完整完成，包含 2527 帧。Worker 实际收到完整 Vec 的时刻没有落盘。旧实现随后逐帧读取和解码此前全部历史，驱动在这段工作中没有按批次让步。冻结源码、运行 sample 和实际 Rust 对照共同支持这条本地处理路径。

Server 的 900 秒租约续租窗口为 `[23:15:56.935Z, 23:17:56.935Z)`。窗口内 Worker 心跳为 0，续租回执为 0。Device 的独立心跳持续，但不能代替 Worker 心跳。租约过期后，第四个本地 model.open 在发送前被权限守卫拒绝，第四个实际付费请求为 0。原 Job 后来保存 failed；正式 cell 的原未决状态保持。

这些证据支持重复历史处理、驱动不让步、心跳饥饿、续租窗口缺失和发送前拒绝之间的链条。三槽正控证明受测等槽路径能继续心跳和续租。正式现场没有逐帧墙钟和完整分支计时，因此没有证明整个 21 分钟空档的唯一原因或耗时分解。当前修复消除重复历史读取，并在帧和控制批次之间归还驱动。原正式批次没有由本轮重放。

## Worker 控制和权限

帧摄取和控制队列各有帧数与时间预算。Worker 驱动在推进执行前后服务心跳和控制。协商心跳间隔仍由原协议决定。

预算在帧与控制之间让步，不抢占单个正在执行的接受操作或文件 I/O。它不构成全路径 25ms 延迟上限。控制先应用取消和续租；无限持续的合法控制流下，Core 推进仍不是本次已证明的保证。

长时间只读验证由 Worker 所属任务执行。Worker owner 保留工作区、Core、V8 和租约权限。启动验证进程前先提交精确 Job、工作区和 batch 的“清理未确认”标记。验证完成后，owner 确认直接子进程已退出，才清除标记并重新核对当前 Job、attempt、Lease 和 fencing。协作取消要求终止进程组，并等待直接子进程退出。清理确认、失败诊断写入或标记清除失败都会保留持久阻塞；关闭和重新打开均拒绝继续接受。进程组终止不证明所有后代在返回时已经回收，也不覆盖自行脱离进程组的后代。进程硬退出与正常协作取消分别记录。

验证启动还需检查两次当前权限：提交清理标记前，以及标记提交后、创建验证任务前。时间沿原驱动入口的外部时间与单调时钟推进。执行步骤或数据库写锁等待跨过截止时，不得沿用入口旧时间启动验证。尚未启动的精确标记可以清除；清除失败时仍保留持久阻塞。最终所属验证 10 项回归已通过，包含真实执行等待、SQLite 写锁等待和精确合法续租。

完成验证后的清理 SQL 也消耗时间。最终接受必须继续使用原驱动时钟，包含清理前后经过的时间。清理后用旧外部时间建立新的单调起点，会遗漏清理耗时。该窗口使用真实 SQLite DELETE 准备阶段的受控延迟验收；它不等于自然写锁等待。原 Deferred 清理事务升级遇到 BUSY 时，必须保留标记并拒绝接受。

旧实现的受控 SQL 延迟回归已实际失败。清理耗时 262ms 后，回执仍为 Applied，内部产生 Accepted 事件并推进 checkpoint revision。首个过期分支失败后，合法续租分支未执行。最终回归实际执行了两个分支：未续租分支耗时 255ms 后拒绝接受，revision 不变；合法续租分支耗时 267ms 后正常接受。

清理之前也必须验证调用者权限。旧路径会按同 JobId 外来调用者伪造的过期时间，先取消合法验证，再返回权限错误。真实负控已证明验证任务由 1 变为 0。修复后先核对工作区来源、租约和精确事件。最终回归证明外来调用被拒绝时，合法任务和清理标记均保留；随后原 owner 正常完成接受。这个新发现的边界不作为原 MiMo 租约事故的原因。

最终接受使用 `BEGIN IMMEDIATE` 先取得写锁，再检查原 Server 租约对应的单调截止。提交前再次检查。锁等待跨过截止时，事务回滚，已接受的工作区版本不推进。该门覆盖验证结果、Observer 结果和公开 checkpoint 入口；测试专用的纯版本入口不进入生产构建。

权限时间使用外部已证明时间加单调经过时间。原租约过期后，等待、工具读取或迟到验证结果都不能取得新的执行权限。续租必须由原有精确绑定的合法回执证明。

## 输入、重试和诊断

InputResponse 接受同一 attempt 已证明的续租。原输入截止独立保留。owner、fencing、session、thread 或 attempt 变化仍拒绝。

一次合法多题调用为每题建立一个产品输入请求。私有调用记录保存原 turn、call、题目映射、截止和部分答案。每题 ACK 证明答案已持久化。Core 答案提交必须包含原 `turn_id` 和 `call_id`。同一 turn 的多个调用分别保留等待者。迟到答案不会转交给其他调用。正常执行时，全部题目完成后，整组答案只交付存活的原 turn/call 等待者一次。进程崩溃后，必须在新的私有 incarnation 中精确重建同一原调用事件，才重投持久答案。旧进程等待者已经不存在。

输入调用已持久化而首个产品输入请求尚未保存时，恢复投影仍使用该调用的原截止。随后合法续租只能延长执行租约。它不能延长原输入请求。

Core 题目允许自由输入时，产品请求用可选 `allowOther` 字段保留这一权限。缺省值为 false。只有明确允许的 SingleChoice 接受选项之外的非空答案；Confirmation 保持原选项集合。Worker 也根据原持久请求检查类型、选项和权限，不能只检查答案非空。文本限制按 Unicode 码点计算，最多 20000 个。空白校验使用 trim，提交保留原文本。旧请求缺少该字段时保持闭集，不自动升级权限。该契约由 schema 生成并同时更新消费者；旧严格客户端需要同步升级。

可选 `allowOther` 字段本身无需 SQL 迁移。多题整改另增加私有 `input_call` 存储及其迁移。事务、重新打开和条件领取使用实际回归验收。

进程崩溃后，原 CodeMode 的 JavaScript 执行现场已经丢失。交互恢复只重建精确输入等待。原脚本记为中断，完整答案进入恢复事实，模型可以据此继续。原脚本后半段的工具操作不会自动执行。恢复准入核对旧 owner 与当前 owner、当前工具目录、原调用绑定和当前权限。同一原调用的恢复由当前 owner 互斥领取。这一边界必须有实际崩溃、答案消费和后置副作用未执行回归。

Core 侧的完整答案、不可变分页索引与恢复证据在同一事务内保存。产品答案提交与 Core 消费分属两个数据库，崩溃恢复依靠已持久化的精确答案重投。每次 Core 注册都有新的私有等待者 incarnation。即使恢复时保留同一 CodexThread，旧 incarnation 的已提交标记也不能证明新等待者已消费。TUI 将答案发送到原 thread、turn 和 call。

普通恢复事实和每页序列化 JSON 均限制为 8KiB。大答案由模型通过专用读取工具取回。每页读取固定头和当前页，并核对摘要、游标绑定与当前读取权限。完整答案 publication 可以读取一次全文；分页及已记录恢复事实重放只读取所需页和固定头。已消费输入的私有事实可以保留，但写入等待跨过权限截止后，返回答案仍需重新通过读取门。共享工具恢复同样在保存事实后重新核验读取权限，再返回事实。

Retry-After 的延期保留为 `DeferredUntil`。延期记录保存原请求身份、下一次 policy attempt 和唤醒时间。等待期间释放请求槽，并检查取消与租约权限。恢复后复用已绑定的 prepared request 正文，发出新的完整物理请求。已持久化正文与原请求身份保持不可变。超限诊断保存有界原始前缀、实际已收字节和已经出现的 usage。

## 存储和 CodeMode

运行账本使用固定大小的头和不可变事件行。事件、身份标记、ACK、receipt 和 outbox 仍在同一事务内提交。精确重复查询检查对应事件。显式投影和证据读取分页重建完整链，并验证摘要。

验收同时检查上层生产调用。底层增量存储通过，不能代替逐条工具事实和命令事件投影的成本验收。

待发队列、续租回执、诊断和 Device 进程状态查询使用精确索引。待发队列容量使用事务内维护的总字节计数和原七维身份槽计数。租约续期仍使用同一槽容量。迁移一次回填旧行；后续 INSERT、UPDATE、DELETE 同步维护计数。验收同时计算容量查询与写入 trigger 的 SQLite VM 步数。已经安装迁移标记后，缺表或弱化的表与 trigger 必须拒绝打开。ACK 查询将已接受序列的上界下推数据库。未来积压和其他 stream 保留。Fusion 候选上下文使用一个所属 `git cat-file --batch` 进程读取 blob。

单个身份槽的计数行缺失时，容量检查使用完整七维索引查询该槽是否仍有原消息。原消息存在就拒绝继续入队。只有原消息和计数行均不存在时，才按新槽处理。该检查不扫描其他槽或完整历史。

诊断待发记录使用独立且不可变的 Job 路由列。查询选中记录后，再核对外层身份与正文。正文损坏不能让所属记录从查询中消失。旧布局迁移必须在一次事务中验证全部旧行，并保留原正文与 transport 字节。迁移标记已存在时，弱化的表、索引或保护 trigger 必须拒绝打开。这是本轮索引优化的验收边界；原基线仍使用全表读取校验。

已完成 ACK 的记录允许重传相同原上传。重复判断核对全部不可变上传字段，并保留原 ACK 状态；变更正文仍拒绝。所属 Job 查询仍逐条核验选中的已 ACK 记录。索引预算证明其他 Job 的历史不增加该查询成本；它不证明同一 Job 的全部已 ACK 历史成本为常数。

Device 待上报索引还有一个已证明的打开边界。迁移标记存在而所属 pending 表缺失时，旧代码会重建空表。真实 SQLite 负控的两个分支均执行：原待上报数量分别由 1 变为 0，原记录和迁移标记仍保留。打开路径必须先校验已迁移布局，再执行首次迁移。迁移的写锁等待也必须继承原打开截止；该预算边界单独验收。它们不是原 MiMo 租约事故的因果证据。

旧 late-migration 对照实际在外部 writer 持锁时通过。原 Deferred 升级立即返回 BUSY，没有复现越过原打开截止。后续 Immediate 迁移需要保留同一打开预算，避免布局守卫新增锁等待。该重排属于守卫的预算保全，不能记为已复现的旧超预算缺陷。

CodeMode 每个 Runtime 使用至多一个可唤醒定时调度器。清除最后一个 timer 或关闭 Runtime 时立即停止并回收。Pending 检查先于值交付，等待期间不深拷贝待保存值。stdio 生命周期使用 driver 所属截止和取消收尾；打开请求被放弃后，调用者等待精确清理屏障。

Kernel 关闭超时覆盖所属 `shutdown_and_wait`。终态留存逐条排空 RuntimeTrace；该外层循环和关闭后的权限清理没有新增整次调用的硬截止。关闭回归只证明具体的清理屏障、原 Core 权威和终态游标边界。

收尾复核发现旧 Device 的 SC-05 停止积压问题。旧真实回归使用 5 个拒绝 TERM 的所属子进程和默认 10 秒停止等待。一次 tick 串行停止全部进程用了 50349ms，超过原 45000ms 目标。原回归没有执行 Server stale sweep。正式 MiMo 事故没有 WorkerStop，且 Device 心跳持续，因此这条路径不是该事故的原因。

SC-05 补入本轮积压边界收尾。Device 下行命令按处理条数和经过时间分批推进。每条停止仍必须完成精确进程回收、持久回执和游标保存，才能确认。尚未处理的帧沿原确认游标在后续 tick 重新读取。验收保留 5 个真实子进程、10 秒等待、45000ms 目标、最终全部终态及精确 ACK。新夹具与旧生产的实际负控退出 101：最大 tick 为 50202ms，最大实际心跳间隔为 50210ms。五个进程退出、五个 Accepted ACK 实际发送及最终游标 5 均在原时间断言失败前完成。修复后同夹具实际退出 0。后续最终 Device 回归的最大 tick 和最大实际心跳间隔均为 10068ms。游标逐 tick 从 1 推进到 5，并实际发送全部五个 Accepted ACK。游标 1 至 4 时，未接受后缀对应的进程仍在运行，且没有停止 intent。默认预算回归已通过。新 CLI 产物与原生链另行绑定。

HTTP 完整终态、EOF 和缓存 completion 的交付出口都需复核取消与精确请求权限。转换前后分别检查，避免 read 返回时已经取消却仍交付成功。拒绝交付时保留实际请求、计费和已知 usage。显式 Cancel／Release 返回前回收缓存中的完整帧。外部取消 token 在发布和读取门观察；已经发布后未再执行任何门时，本轮不承诺后台立即回收。缓存发布与取消使用同一锁顺序，避免取消后再次发布完整帧。私有记录只保留有界身份元数据及固定大小的计费事实。身份超过限额时省略，不截断；已知计费独立保留。缓存没有原始 HTTP 字节，不能为缓存拒绝捏造正文或接收字节数。缓存路径与普通 Device 正式模型路径分别验收。

## 基准控制器

控制器即时发布进入调度、已收尾、活跃、未调度、未决、停派和排空状态。`started` 统计进入调度的 cell，包含复用终态和未选中配置。`active` 统计尚未返回的调度调用。两者都不等于实际模型请求或原生 Job 数。证据持久化失败会停止新任务，并等待已启动任务保留其结果。
