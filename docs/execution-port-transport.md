# 远程执行通道边界

Execution Port 内层 v1 和远程交换外层 v1/v2 均保留整数数组形式的帧字段。内层帧上限为 256 KiB，请求正文上限为 1088 KiB，应答正文上限为 2 MiB。构造、编码和解码均检查实际编码尺寸；应答分页同时受 128 条和正文尺寸约束，剩余消息继续留在原队列。

新候选按最多 64 KiB 原始数据分块，并根据完整帧中的租约、身份和编码开销缩减预算。首次保留前验证全部帧的线上编解码；不可变内容与分块索引独立保存，ACK 只更新小记录。重启时验证完整内容，发送资格检查只读取当前分块。

升级时，旧 JSON 和已拆分 BLOB 的上传记录都检查实际传输尺寸。可发送或已收到最终 ACK 的旧计划保持原身份与完成状态；超限且未完成的计划在同一 SQLite 事务内退休旧 outbox、记录旧新关联，并为原内容摘要建立新的上传、消息身份和有界分块。旧 ACK 只匹配退休记录，不推进新计划。

新 `artifact.open.replacesArtifactId` 请求绑定原上传。Server 校验候选摘要、字节数、来源权限及冻结元数据；事务内保存替换回执并退休未完成的旧流，避免同时占用两份未完成配额。若旧流已完成，ACK 的 `retainedArtifact` 返回原引用和零序号，Worker 将该引用封入最终结果。升级后的分块只在替换 open 被确认后进入发送队列；丢失应答及重启继续重放同一替换身份。

| Worker 错误码 | 含义 | 行为 |
| --- | --- | --- |
| `REMOTE_WORKER_TRANSPORT_UNAVAILABLE` | 连接中断、超时、408、429 或 Server 5xx | 保留消息，按现有退避重试 |
| `REMOTE_WORKER_BACKPRESSURE` | Server 已处理 ACK/拉取，上行帧尚未接受 | 保留上行消息重试，同时消费收到的控制消息 |
| `REMOTE_WORKER_AUTHENTICATION_REJECTED` | 401、403 或不可用的认证令牌 | 当前进程结束，由 Device 处理退出及重新授权 |
| `REMOTE_WORKER_PROTOCOL_INVALID` | 永久协议错误、错误方向或其他拒绝状态 | 当前进程结束，保留诊断类别 |
| `REMOTE_WORKER_MESSAGE_TOO_LARGE` | 最终编码超限或 HTTP 413 | 当前进程结束，保留尺寸错误类别 |

只有认证拒绝设置认证失效状态。HTTP 客户端使用标准解析器，支持定长、chunked 和连接结束形式；状态分类先于正文读取，读取后的正文仍受 2 MiB 上限约束。

Server 应答配额按 Worker/instance 隔离。接收业务消息前先认证、处理 ACK 并检查应答空间。外层 v2 即使处于背压也返回已有控制消息页，以 `frameAccepted=false` 明确拒绝本次上行业务帧；Worker 仅确认已发送的 ACK 前缀并保留上行消息。此分支跳过业务入口和新增调度。分页预算包含接收状态字段，审批、取消、停止消息保留到确认。只有权威确认撤销的身份和已被新实例取代的身份才退休残留应答。

Worker 消费 `artifact.ack` 时只做身份、顺序、摘要校验及持久化状态推进。Replay/替换握手释放的新分块已进入 durable outbox；最终候选回执还要可靠保存 final freeze、JobOutcome 和必要的 Observer 取消意图，之后才允许确认控制消息。注册、Runtime、Model、JobOutcome、心跳等纯回执消费也只落库，不触发后续发送。心跳不先扫业务 outbox。后续网络发送由驱动循环负责，发送失败不会撤销已可靠消费 ACK 的确认资格；校验或持久化失败仍返回错误并保持控制消息未确认。

`WorkerExecutionPort::failure_kind` 保留 Worker 级背压、暂时不可达、单帧拒绝和端口终止四类错误。背压、连接失败、认证/协议终止在首次失败时结束当前批次；单帧拒绝可继续处理本批其他证据。正常 flush 每次最多读取 64 条 outbox 记录、发送约 512 KiB 的规范 JSON，并在 250 ms 调度预算到达后让出下一次发送。单个合法大帧可独占一批，已开始的交换使用端口原有超时完成，不因调度预算取消回执/账务提交。SQLite 分页和恢复游标避免每轮加载全部候选分块；被背压拒绝的帧保持 pending。外层主循环先消费并确认控制消息，再推进下一发送批次和心跳。


部署顺序为先升级 Server，再升级 Worker。新 Server 继续接受外层 v1，但背压时仍返回 503，旧 Worker 需升级至 v2 才具备持续排空路径；新 Worker 要求 v2 接收回执，拒绝将缺失回执视为发送成功。Artifact catalog 从 v2 原子升级至 v3，增加替换回执表；旧版本程序不能直接打开 v3 catalog。
