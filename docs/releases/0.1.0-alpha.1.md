# WinWinCode 0.1.0-alpha.1

`0.1.0-alpha.1` 是 Rust Control Plane/Execution Worker 架构的首个 alpha 候选。

## 产品组成

- **Client 静态应用。** Client Chat 是默认界面，StrongFlow 是高级交付界面；部署时只用 `runtime-config.js` 的 `serverUrl` 连接 Server。
- **Rust Server。** Control Plane 是 ProductSession、Delivery、审批、策略、审计、发布和 HTTP/WebSocket 的唯一业务写入者。
- **Rust Worker。** Execution Worker 受 lease/fencing 约束，拥有 checkout、内嵌 Codex Core、工具、沙箱、runtime events 和 artifacts。
- **Local 同进程模式。** `winwincode-server` 是启动入口，通过 `winwincode-local` library 组装本地 Worker。
- **分离模式。** Server 与远程 Worker 只通过版本化 ExecutionPort v1 交换消息；Client 不直连 Worker。

旧 TypeScript Host、DSH/Cordis 后端、N-API/native loader 和 CLI fallback 已从生产路径删除。

## 版本与协议

Node 产品 manifest 与 Cargo workspace 统一为 `0.1.0-alpha.1`。Control Plane 使用 `winwincode/v1`，OpenAPI 版本为 `1.0.0`；本地与远程 Worker 共用 ExecutionPort v1。Delivery 数据结构版本为 3。

## 支持平台

- `aarch64-apple-darwin`
- `x86_64-apple-darwin`
- `aarch64-unknown-linux-gnu`
- `x86_64-unknown-linux-gnu`

每个平台原生构建 Server、Worker 和 Worker 内部 Kernel helper。Client 静态文件在四个平台证据中必须字节完全相同。

## 供应链证据

同一干净 commit 的发布证据包含：

1. frozen pnpm install、locked Cargo metadata、格式、类型、strict clippy、测试、干净安装和产品纵向；
2. 固定 `SOURCE_DATE_EPOCH` 下，在同一物理 Cargo target 完整清空前后执行两次冷构建，并逐文件比较 SHA-256；
3. 四平台 artifact manifest 与 `SHA256SUMS`；
4. 与 Worker 一起分发并通过 Ed25519 验证的 Kernel helper 签名清单；
5. Apache-2.0 `LICENSE`、`NOTICE` 和必要第三方通知；
6. 同 commit 的 Client 远程 Server、本地同进程、分离 Worker、真实 Provider/Delivery、重启和取消证据。

详细命令见 [发布流程](../releasing.md) 和 [产品发布证据门禁](../release-gate.md)。

## 当前限制

这是 alpha 证据候选，脚本不会自动发布包、创建 tag 或 GitHub Release。外部 IdP 和可选连接器不属于核心发布阻塞项；真实 Provider 运行仍需要显式的 0600 凭据文件和当前人工授权。
